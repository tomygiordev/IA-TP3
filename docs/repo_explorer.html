TP 3 - MLP
Explorador del repositorio

Una MLP simple, explicada paso a paso.

El objetivo de la red es leer una frase de una critica de cine y predecir si expresa una opinion positiva o negativa (analisis de sentimiento binario). Este documento explica como esta organizado el proyecto, que hace cada parte del pipeline, que experimentos se entrenaron y por que se tomo cada decision tecnica.

01 / flujo del sistema

La arquitectura queda como una linea de montaje auditable.

Cada bloque del flujo se puede seleccionar para ver por que existe. Dos reglas atraviesan todo el sistema: el conjunto de test no se usa para elegir hiperparametros y el vectorizador solo aprende del conjunto de entrenamiento.

Hugging Face dataset

Se usa `cornell-movie-review-data/rotten_tomatoes`: 10.662 frases cortas de criticas de cine en ingles, cada una etiquetada como positiva o negativa.

  • Splits oficiales: 8530 de train, 1066 de validacion y 1066 de test.
  • Balanceado 50/50 entre clases, lo que simplifica leer las metricas.
  • Chico y de textos cortos: permite entrenar muchas veces en una PC comun.
02 / estructura

Cada carpeta tiene una responsabilidad concreta.

La estructura separa codigo, evidencia generada y documentacion. El detalle de cada archivo se ve directamente explorando las carpetas.

src/Codigo del pipeline: configuracion, datos, modelo, entrenamiento y evaluacion.
results/Evidencia generada por los entrenamientos: metricas y graficos.
docs/Documentacion tecnica: arquitectura, experimentos, resultados y fuentes.
docs/materials/Consigna oficial y teoria de catedra.
docs/prompts/Prompts usados como apoyo durante el TP.
report/Guia para redactar el informe final.
03 / hiperparametros

Los experimentos no son decoracion: prueban capacidad, ritmo y regularizacion.

La seleccion se hace por F1 de validacion. Test queda reservado para reportar desempeno final. Los resultados numericos vigentes estan en results/metrics.csv.

e0_baseline

MLP chica que sirve como punto de comparacion para el resto de los experimentos.

Hipotesis: una red simple ya resuelve el problema de forma aceptable y permite medir el efecto de cada cambio posterior.

04 / evidencia visual

Los graficos muestran comportamiento, no solo numeros sueltos.

La curva de overfitting es especialmente util: train queda perfecto mientras validacion se degrada.

05 / preguntas frecuentes

Los conceptos detras de las decisiones.

Estas preguntas resumen los conceptos centrales del TP: separacion de conjuntos, eleccion de metrica y sobreajuste.

El objetivo no es la arquitectura: es entender el proceso.

El TP demuestra como se entrena una red neuronal multicapa, como se comparan hiperparametros con un conjunto de validacion, como se reconoce el sobreajuste y como se interpreta el resultado final con una matriz de confusion.

  • Consigna cubierta: Keras Sequential, MLP, Hugging Face y clasificacion binaria.
  • Metodologia: el vectorizador se adapta solo con train y el modelo se elige por validacion.
  • Evidencia: metricas, matriz de confusion y curvas de aprendizaje.
F1 combina precision y recall en un solo valor. Accuracy sirve como referencia porque el dataset esta balanceado, pero F1 permite discutir mejor los falsos positivos y falsos negativos.
